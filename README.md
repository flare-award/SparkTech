# SparkTech

**Анализ хранилища и безопасная оптимизация Android-телефона с компьютера под Windows — через официальный Android Debug Bridge (ADB).**

SparkTech — это честная утилита: она показывает, что реально видит в общей памяти телефона, объясняет, почему файл попал в список, и **никогда ничего не удаляет без вашего подтверждения**. Программа не требует root, не обходит защиту Android, не просит пароли и не обещает «ускорения на 100 %».

```
 ┌──────────────┐   HTTP (127.0.0.1, токен)   ┌──────────────────┐   adb shell   ┌─────────┐
 │ Интерфейс     │ ◀──────────────────────────▶ │ Ядро SparkTech   │ ────────────▶ │ Android │
 │ WebView2/браузер│                            │ ADB · сканер ·   │ ◀──────────── │ телефон │
 └──────────────┘                              │ удаление · оптимизация │            └─────────┘
                                               └──────────────────┘
```

## Что умеет и чего не делает

**Умеет:**

| Возможность | Как реализовано |
|---|---|
| Определение состояния подключения | `adb devices -l` → 4 понятных состояния: не подключён / ожидает подтверждения / готов / недоступен. Название модели, производитель, версия Android, ABI. |
| Выбор устройства при нескольких подключённых | Селектор в боковой панели и на экране подключения. |
| Сканирование общей памяти | `find` по реально существующим пользовательским каталогам; потоковый разбор вывода с прогрессом и отменой. |
| Категории | Крупные файлы, загрузки, архивы, APK, временные файлы, дубликаты по хешу содержимого. |
| Объяснение результатов | Для каждого файла: причина попадания, уровень осторожности, предупреждения. |
| Поиск, фильтры, сортировка, мультивыбор, CSV | В таблице результатов. |
| Удаление с защитой | Предпросмотр списка и суммы, подтверждение, проверка пути, проверка размера, отчёт «удалено / ошибки». |
| Оптимизация | 7 действий с описанием эффекта, ограничений, побочных последствий и отмены; результат проверяется, а не предполагается. |
| Журнал операций | Локальный JSONL без паролей и содержимого файлов. |

**Сознательно не делает:**

- не очищает кэш приложений и **не создаёт видимость** этого (кэш чужих приложений недоступен без специальных привилегий; вместо этого — инструкция для телефона);
- не сканирует `/data/data`, системные разделы, `Android/data`, `Android/obb` — и честно пишет об этом в отчёте о покрытии;
- не удаляет системные файлы и данные приложений (жёсткий чёрный список путей);
- не очищает RAM, не «закрывает приложения ради ускорения», не отключает системные службы;
- не делает сброс устройства, не отключает защиту, не трогает настройки разработчика;
- не скачивает adb и любые другие компоненты;
- не отправляет данные в интернет, не содержит аналитики;
- не обещает восстановление удалённых файлов.

## Установка и запуск

### Требования

- **Windows 10/11** (проверялась разработка на Linux; сборка `.exe` — для Windows, см. ниже).
- **Python 3.10+** — только если запускаете из исходников (готовый `.exe` Python не требует).
- **Официальные Android SDK Platform-Tools** — см. [раздел ниже](#официальные-platform-tools-adb).

### Вариант 1 — готовый `.exe`

```
dist\SparkTech.exe
```

Приложение откроет нативное окно (WebView2). Если WebView2 Runtime отсутствует, интерфейс откроется в браузере по умолчанию.

### Вариант 2 — из исходников

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -e .
# необязательно: нативное окно вместо вкладки браузера
pip install -r requirements-desktop.txt
python -m sparktech
```

Полезные ключи:

| Ключ | Назначение |
|---|---|
| `--adb "C:\platform-tools\adb.exe"` | явный путь к adb |
| `--port 8123` | фиксированный порт локального интерфейса |
| `--browser` | открыть в браузере, даже если доступно окно |
| `--no-window` | только локальный сервер (для отладки) |
| `--data-dir PATH` | каталог настроек и журнала |
| `--version` | версия |

Сервер **всегда** поднимается на `127.0.0.1` со случайным портом и случайным токеном сессии; при закрытии окна он останавливается (`server.shutdown()` + выход процесса). Порт наружу не публикуется.

## Официальные Platform-Tools (adb)

SparkTech **не содержит, не скачивает и не распространяет** adb: это компонент Google, распространяемый по **Android SDK License Agreement**.

1. Скачайте архив **только** с официальной страницы: <https://developer.android.com/tools/releases/platform-tools>.
2. Распакуйте так, чтобы получился путь `platform-tools\adb.exe` (рядом — `AdbWinApi.dll`, `AdbWinUsbApi.dll`).
3. Укажите путь одним из способов:
   - **Настройки → Путь к adb.exe** в самой программе (сохраняется локально);
   - переменная окружения `SPARKTECH_ADB`;
   - каталог `vendor\platform-tools` рядом с `SparkTech.exe`;
   - стандартные места Android SDK (`%LOCALAPPDATA%\Android\Sdk\platform-tools`, `ANDROID_HOME`);
   - PATH.

Программа показывает, какой именно `adb` найден и его версию. Если adb не найден — понятное сообщение и ссылка на официальную страницу; имитации работы не будет.

**Включение в сборку** (по желанию, вручную): положите файлы из `platform-tools` в `vendor\platform-tools` **перед** сборкой. `SparkTech.spec` упакует их в `vendor/platform-tools`. При этом вы как распространитель обязаны соблюдать Android SDK License Agreement.

## Подключение телефона

1. **Параметры разработчика:** Настройки → О телефоне → 7 нажатий на «Номер сборки».
2. **Отладка по USB:** Настройки → Система → Для разработчиков → «Отладка по USB». На Xiaomi/Redmi дополнительно: «Установка через USB», отключить «Отладка по USB (уровень защиты)».
3. **Кабель:** нужен кабель с передачей данных; в уведомлении «Использование USB» выберите «Передача файлов».
4. **RSA-запрос:** на экране телефона нажмите «Разрешить» (можно отметить «Всегда разрешать с этого компьютера»).

> **MTP недостаточно.** Режим «передача файлов» без отладки по USB не даёт ADB доступа. SparkTech работает только через ADB.

Состояния, которые показывает программа:

| Состояние | Что делать |
|---|---|
| Телефон не подключён | Проверить кабель, порт, включён ли ADB |
| Устройство обнаружено, ожидается подтверждение отладки | Подтвердить RSA-запрос на телефоне, затем «Проверить» |
| Устройство подключено и готово | Можно выбирать раздел |
| Устройство недоступно или возникла ошибка | Переподключить кабель, «Перезапустить adb-сервер» |

Отключение кабеля во время работы не подвешивает интерфейс: каждая команда имеет тайм-аут, а состояние опрашивается периодически.

## Раздел «Очистка»

Сканирование обходит **только доступные без root пользовательские каталоги**:

```
Download, Downloads, DCIM, Pictures, Movies, Music, Documents,
Android/media, Bluetooth, Ringtones, Alarms, Notifications,
Podcasts, Recordings, Telegram, WhatsApp
```

Исключаются (`-prune`): `Android/data`, `Android/obb`, `.thumbnails`, `.trashed`, `LOST.DIR`.

### Как формируется список

| Категория | Правило | Осторожность по умолчанию |
|---|---|---|
| Крупный файл | размер ≥ порога (50 МБ…1 ГБ, настраивается) | средняя |
| Загрузки | путь содержит `/Download`, `/WhatsApp/…Documents` и т. п. | средняя |
| Архив | `.zip .rar .7z .tar .gz .iso …` | средняя |
| Установочный пакет | `.apk .apks .xapk .apkm .aab` | средняя |
| Временный файл | `.tmp .part .log .bak`, каталоги `cache/tmp/…` | высокая (вне явных cache-каталогов) |
| Дубликат | одинаковый размер + одинаковый SHA-256 первых 64 КиБ (или полный SHA-256) | средняя |

**Крупный, старый или незнакомый файл не называется мусором.** В причинах прямо написано: «Сам по себе размер не делает файл мусором». Файлы в `DCIM`, `Pictures`, `Documents`, мессенджерах получают **высокую** осторожность и предупреждение.

### Дубликаты

- Сравниваются только файлы ≥ 1 МБ (настраивается) и одинакового размера.
- По умолчанию — частичный хеш (первые 64 КиБ): быстро, но возможны ложные совпадения — SparkTech об этом предупреждает и предлагает полное хеширование.
- Ограничение: не более 200 файлов (и 512 МБ при полном хешировании) за один проход; при превышении показывается предупреждение.
- Оригиналом считается файл с наименьшим числом причин для удаления.

### Удаление

1. Отметьте файлы (в таблице или «Выбрать всё видимое»).
2. Нажмите «Удалить выбранные» / «Удалить» у строки.
3. Появится окно со **списком, количеством и общим размером** и предупреждением о необратимости. Кнопка активна только после отметки «понимаю, что файлы будут удалены безвозвратно».
4. Каждый файл перед удалением проверяется: существует ли, обычный ли это файл (не каталог, не симлинк), совпадает ли размер со сканированием.
5. После `rm -f` выполняется **повторная проверка существования** — Android-`rm` иногда возвращает 0 при отказе.
6. Отчёт: отдельно «удалено» и «не удалено» с причиной.

Пути передаются в оболочку только через `quote_remote_path()` (POSIX-кавычки `'…'\''…'`), поэтому пробелы, кириллица, `$()`, `;`, `*` безопасны. Системные пути, `/data/*`, `Android/data`, `Android/obb` отклоняются до обращения к устройству.

## Раздел «Оптимизация»

Список действий **проверяется на конкретном устройстве** (реальным запросом), каждое помечается как доступное/недоступное с пояснением.

| Действие | Что делает | Эффект | Ограничения | Отмена |
|---|---|---|---|---|
| Попросить систему освободить кэш (`send-trim-memory` + `fstrim`) | системное событие + trim накопителя | иногда освобождает место, ускоряет запись на флеш | объём неизвестен, часто 0; скрытые кэши недоступны | менять нечего |
| Пересоздать индекс медиа | `content call … scan_volume` | исправляет «галерея не видит файл» | не на всех прошивках (проверяется) | не требуется |
| Отключить анимацию окон / переходов / элементов | `settings put global …_scale 0` | интерфейс субъективно быстрее | это **не** рост производительности | да: исходное значение сохраняется |
| Не гасить экран при зарядке | `stay_on_while_plugged_in=7` | удобно при длинных операциях | расход энергии, риск выгорания | да |
| Перезапустить системную оболочку | завершить process systemui | лечит зависший UI | кратковременное гашение экрана | не требуется |

Все действия с настройками: перед изменением читается текущее значение, после записи — **читается повторно**; если значение не подтвердилось, статус будет «не выполнено», а не «успешно». Кнопка «Отменить» возвращает сохранённое значение.

Действия, требующие участия человека, показываются как инструкция со статусом **«Требуется действие пользователя»**: очистка кэша приложений (`pm clear` уничтожает все данные, включая логины, поэтому не автоматизируется), ограничение фоновой активности, системное управление памятью.

## Сборка Windows `.exe`

```powershell
# PowerShell (рекомендуется)
powershell -ExecutionPolicy Bypass -File scripts\build_windows.ps1

# или командная строка
scripts\build_windows.bat
```

Что делает скрипт: создаёт `.venv`, ставит `pytest`, `pyinstaller`, `pywebview`, прогоняет тесты, проверяет наличие `vendor\platform-tools\adb.exe`, собирает `dist\SparkTech.exe` (один файл, GUI без консоли).

Ручная сборка:

```powershell
python -m pip install pyinstaller pywebview
python -m PyInstaller SparkTech.spec --noconfirm --clean
```

Результат: `dist\SparkTech.exe`. Статические файлы интерфейса упакованы внутрь (`sys._MEIPASS`), `adb` — только если вы положили его в `vendor\platform-tools` вручную.

Готовая CI-сборка: `.github/workflows/build.yml` собирает `SparkTech.exe` на `windows-latest` и прикладывает артефакт.

### Проверка без телефона: макет adb

`scripts/mock_adb.py` — тестовый макет CLI `adb`, который выполняет `shell`-команды
настоящей POSIX-оболочкой по «файловой системе телефона» в каталоге
`$SPARKTECH_MOCK_ROOT`. Это позволяет прогнать **весь боевой конвейер** (транспорт,
экранирование, потоковый разбор `find`, `rm`, проверку результата) без устройства:

```bash
mkdir -p /tmp/mockphone/Download
truncate -s 800M "/tmp/mockphone/Download/video.mp4"
SPARKTECH_MOCK_ROOT=/tmp/mockphone python -m sparktech --adb "$PWD/scripts/mock_adb.py"
```

Макет не эмулирует Android: `getprop`, `df`, `settings` и `pidof` в нём подделаны явно.
Он нужен для проверки SparkTech, а не поведения реальной прошивки.

Все тесты работают без телефона: транспорт ADB заменяется тестовым двойником (`tests/conftest.py`), боевой код сканера/удаления/оптимизации при этом не меняется.

## Архитектура

```
sparktech/
├── __main__.py            точка входа: сервер + нативное окно/браузер
├── core/
│   ├── process.py         единственное место запуска процессов (без shell=True, тайм-ауты, отмена)
│   ├── adb.py             поиск adb, устройства, свойства, команды shell
│   ├── remote_path.py     экранирование и защита путей
│   ├── scanner.py         обход каталогов, прогресс, покрытие
│   ├── classify.py        правила категорий, осторожность, дубликаты, фильтры
│   ├── deleter.py         безопасное удаление и отчёты
│   ├── optimizer.py       каталог действий, проверка, выполнение, отмена
│   ├── models.py          модели данных (без зависимостей)
│   ├── jobs.py            фоновые задания: прогресс, отмена
│   └── store.py           настройки, журнал, сохранённые значения
└── web/
    ├── server.py          локальный HTTP API (127.0.0.1 + токен)
    └── static/            index.html, styles.css, app.js
```

Интерфейс, работа с ADB, логика сканирования и действия разделены: `core/*` не знает про HTTP, а `web/*` не содержит логики удаления.

## Приватность и безопасность

- **Только loopback.** Сервер слушает `127.0.0.1`; при закрытии приложения останавливается.
- **Токен сессии.** API требует `X-SparkTech-Token`, который выдаётся только в HTML локального интерфейса. Посторонняя вкладка браузера не может управлять приложением (CSRF).
- **Нет внешних ресурсов** в интерфейсе: ни шрифтов, ни CDN, ни аналитики (проверяется тестом).
- **Нет сетевых запросов к интернету** из кода: только локальные вызовы и `adb`.
- **Журнал** (`%LOCALAPPDATA%\SparkTech\operations.log`) хранит тип операции, серийник, счётчики и код результата — без паролей и содержимого файлов. Полные пути попадают только в интерфейс и в отчёт, который вы видите сами.
- **Ничего не удаляется и не меняется автоматически.** Никаких «умных автоочисток».
- **Тайм-ауты** у каждой команды; ожидание `find` ограничено ещё и по «молчанию» устройства.
- **Без root.** Программа не запрашивает `su`, не использует эксплойты и не обходит scoped storage.

## Известные ограничения

- **Нужна отладка по USB.** Без неё ADB-доступ невозможен; MTP-режима недостаточно.
- **Android 11+ (scoped storage).** Часть каталогов может быть недоступна `adb shell`; SparkTech покажет их как «нет доступа» в отчёте о покрытии, а не сделает вид, что всё проверил.
- **Кэш приложений недоступен.** Ни сканирование, ни очистка кэша чужих приложений без специальных привилегий невозможны — только инструкция для настроек телефона.
- **`find -printf`** — расширение GNU/toybox. На устройствах, где его нет, область помечается как непрочитанная (без ложных результатов).
- **`send-trim-memory`/`fstrim`** могут быть запрещены прошивкой; это отражается в отчёте.
- **Перезапуск systemui** не на всех прошивках разрешён; если новый PID не подтверждён — статус «требуется действие пользователя».
- **Восстановление файлов не реализовано** и не обещается.
- **Один экземпляр приложения.** Параллельный запуск двух копий не блокируется жёстко (порты разные), но журнал общий.
- Интерфейс рассчитан на десктоп; на узких экранах таблица перестраивается в карточки.

## Итог: что проверено, а что — нет

**Проверено в этой среде:**

- **188 автоматических тестов** (`pytest`) — все проходят (2 пропуска: проверки, требующие POSIX-оболочки, на Windows);
- **сквозной сценарий в браузерном движке** (jsdom, без скриншотов): подключение →
  состояние «готово» → сканирование с прогрессом → таблица результатов → «Почему?» →
  фильтры/поиск → «Оставить» → окно подтверждения → удаление → отчёт → экран
  оптимизации с 7 действиями (5 доступно, 2 с пояснением) → отчёт;
- **реальный процесс ADB-транспорта**: сканирование и удаление через макет `adb` на
  POSIX-оболочке, включая файл с именем `it's files/$(reboot); name.zip`;
- локальный сервер: только loopback, обязательный токен, запрет обхода каталога, работа через произвольный `Host` (прокси), отчёты и отмена заданий;
- веб-интерфейс отдаётся корректно, статика на месте, связность JS ↔ HTML проверена статически и через тесты;
- разбор реальных форматов вывода `adb` (строки `devices -l`, `getprop`, `find`);
- проверка доступности действий оптимизации и подтверждение записи настроек
  (в том числе «Отменить» возвращает стандартное значение, если настройка была `null`);
- отчёт о покрытии: области сканирования, недоступные каталоги и статистика
  «не предложено к удалению» (мелкие файлы, закрытые каталоги, прочее);
- экранирование путей проверено на настоящей POSIX-оболочке;
- конфигурация PyInstaller и CI проверены статически (включая метаданные версии
  `packaging/version_info.txt`, которые раньше терялись из-за `.gitignore`);
- тесты прогоняются в CI на **Python 3.10 и 3.12** под Linux и Windows.

**Не проверено (и не заявляется как проверенное):**

- визуальный вид окна в реальном браузере: в среде нет ни Chromium, ни WebView2,
  поэтому вёрстка проверена только структурно (jsdom, тесты связности), без скриншотов;

- **работа на реальном Android-телефоне** — в среде разработки не было устройства и даже `adb`;
- **сборка и запуск `SparkTech.exe`** — среда Linux без `libpython3.11.so`, собрать исполняемый файл здесь невозможно. Сборка `.exe` требует Windows: скрипты `scripts/build_windows.ps1` / `.bat` и CI-workflow готовы, но сам `.exe` не собран и не запускался;
- **нативное окно WebView2** — pywebview в среде отсутствует;
- **поведение прошивок конкретных производителей** (Xiaomi, Samsung, Huawei и др.) — проверялось только по документации Android.
